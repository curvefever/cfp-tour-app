# Open items

Known gaps, accepted limitations and undecided questions. Read when planning a feature, diagnosing a bug, or closing out a build (update it when a build closes or changes an item). Larger future projects are in `docs/roadmap.md`.

## Known gaps
- **Partial automated test coverage** — React components, hooks and server functions have no direct tests (`@testing-library/react`/`jsdom` installed, not configured). See `AGENTS.md`, "Testing". The count is what `pnpm test` reports, plus 7 Playwright smoke tests; the screenshot spec (`pnpm run test:screens`) takes pictures and asserts little. The Tournaments hub added the sync, lifecycle, visit, info, presence and cleanup-script tests; its server functions are covered through their pure validators and planners, and by live checks on the test site (the refusal of a screenshot upload or delete on a finished tournament was not live-tested).
- **Phone layouts (phase G of the visual redesign) are not built yet.** The pages work at 390 px but use the desktop designs; Bracket shows all rounds side by side, Standings is the full table. The Admin and Setup screens stack their panels but have no phone design.
- **A roster loaded under one format can be generated under another.** `SetupView`'s `changeFormat()` never touches `state.players`; `rosterKeys()`/`generateTournament` accept whatever shape the roster already has (string or `TournamentTeam`) regardless of the selected format, so switching game format after loading a roster — by hand, or via "Copy settings from a past tournament" changing the format — and generating without reloading produces a schedule of the wrong unit type. The Setup panel already warns "load the roster again" when a copy changes the format; nothing currently blocks generating anyway. Noticed during the copy-settings live check (see the log entry).
- **A score correction in a double-elimination or waterfall round, after the next round is drawn, doesn't re-route.** Next Round steps forward to the drawn round unchanged (`drawnAheadStatus()` is `'locked'`), because the round already pushed its units into `pendingBracketSeeds` and a re-draw can't rebuild them. A full undo would need snapshot/restore of the pending pools, lucky losers and round shapes.
- **Before Confirm & Start, the Bracket an admin sees marks Round 1 "NOW".** The tab is shown from Generate (read-only until the start), and the round header takes the current round as being played; a pre-start label ("Next" or none) is not built.
- **A live graph edit can move a Qual band boundary into an unresolved tie.** After the bracket is entered, tie resolutions are kept, but they only cover the old boundaries; a new boundary inside a tied cluster is then decided silently by the default order. Rare, and a changed line-up of a reached round is still caught by the replay compare.
- **Text in the coloured rows sits slightly above the middle** (Bracket, Rankings, Standings and the other player + score rows). Raised by the organiser; parked so it can be done together with a possible small typeface change, which would move the same metrics. The likely cause is the font's ascent/descent against the row's line height, so one fix in the shared row or typography classes should cover every row.

## Accepted limitations (not building without an organiser request)
- **Two admins editing the same Setup field at the same moment: the last save wins.** A name tag ("Alex is editing") warns, and the field being typed in is protected from incoming changes, but nothing merges two edits. Two tabs of one account share one presence key, so a blur in one tab can hide the other's tag until its next heartbeat; a tab that crashes leaves its tag for up to 30 s, and its entry stays in the database (a few bytes) until that admin next focuses a field or the tournament is deleted. The waterfall graph editor has no name tag (it has no text control), and the Grand Final losers-bracket target shows its tag on the label it shares with the winners-bracket target.
- **The rules text saves when its box is left**, not while typing, so a snapshot from the database never cuts into it; an admin who closes the tab with the cursor still in the box may lose that last edit.
- **Screenshots are stored as base64 text** in `media/{id}/{imageId}` of the Realtime Database (shrunk to about 5-10 KB each, at most 4 per tournament, read once per browser), not in Firebase Storage. Plenty for the free plan; revisit if an organiser wants larger images.
- **The Tournaments page and the Admin list have no pagination or search**; every `index/` entry is read as a whole (a few hundred bytes each).
- **No extra reserves for a waterfall, or for a group stage.** Adding a reserve stays blocked once either starts (its graph or group schedule is built for the exact head count; allowing it during qualification would only grow the eliminated tail). A no-show is replaced one for one with ⇄ Swap, until the first elimination.
- **A withdrawn unit's name used again for a new entrant** (the individual swap prompt only refuses names in the current roster) makes the live graph edit's replay map old line-ups to the new person. Edge case, not fixed.
- **Bracket preview after a waterfall withdrawal.** The Bracket tab projects an undrawn waterfall round from its routing (`predecessorsOf`, `bracket.ts`), so after a withdrawal it can still list a slot for a rank the short source room no longer has (e.g. "R1.B 8th"), until the round is drawn. Cosmetic; found at the planner's final review.
- **Standings displays ignore a partly scored current-round room, but advancing with an unscored unit still uses that partial room for the real cut.** The Standings tab, Bracket column, banner rank and Rankings badge wait for a room's last score; `roomBasedComputeAdvancement` does not.
- **FFA counts that can't fill rooms of 6–8 are seated in smaller rooms** (9 → [5,4], 17 → [6,6,5]), by the organiser's decision; planned counts avoid this, organiser-entered counts can't. A few Shared-Final FFA configurations (17–19 entrants with 3–4 LB qualifiers) also fall back to it.
- **A removal can leave the current Kings Valley round, and rarely the next, below the minimum** (holding fallback; e.g. 7 [4,3] with a removal from room 2 has no seatable cut). The organiser can fill the room with a reserve.
- **Anonymous Finals exclude grand-final (race) Finals and team formats.** Race progression (`progressGrandFinalRace`, `finals.ts`) reads the two real finalists' score keys, so a placeholder-scored game would stall it; team Finals read a real `TournamentTeam` via `buildTeamMap()`, which a placeholder never has. See "Anonymous Finals matches, v1" in the log.
- **Live corrections have gaps by design** (mid-tournament corrections): no edit history or undo; no live edits of seeding method, pooling round count, Semis/Final sizes or LB qualifiers; no mid-bracket advancement edits for shared-Final double elimination; no line-up edits of scored rounds, fixed-draw pooling rounds, or in group stage, either double elimination, Kings Valley or waterfall; no moving into or out of byes. Details: `docs/rules.md`, "Line-up corrections".
- **Equal lucky-loser shares are split silently by room order.** `pickLuckyLosers` sorts candidates by relative room share and the sort is stable, so two candidates with exactly equal shares at the cut-off are separated by the earlier room, with no tie shown or resolved by the organiser. Rare with real scores; nothing flags it.
- **The followed player or team is stored once per browser**, not per tournament, so it carries over to another tournament, where the Bracket reads "Not in this bracket" until the box is emptied.

## Awaiting organiser feedback
- **Two levels of "where do I stand"** — the Bracket standings column and the Standings tab. The Bracket's "Top N in standings →" badge and Rankings' pool-rank badge are gone (the standings column's exit icon says where the standings lead; Rankings says where each unit stands in the tournament, in the Bracket's round names: "Standings · #25" there, "Out in standings · #25" in the Bracket banner). Open until the organiser judges whether both remaining levels are needed.
- **Waterfall depth in Rankings.** Units eliminated in a waterfall are ordered like any other round (later round in play order first, then place, relative share, pooling standings); neither room depth nor graph level is used. A waterfall graph can take any shape, so no single depth order fits every graph (e.g. two parallel rounds such as R6B and R6C in the 32-player example, played one after the other only because rounds run in sequence). Open until the organiser settles a rule.

## Notes for live checks and the screenshot harness
What the 2026-10 live checks in the built-in browser showed about driving the app by script; read before a check that types, copies or captures.
- **Typing into a controlled field**: setting `value` and dispatching an event is not always enough (the team score inputs stored nothing). Focus the field, select it and call `document.execCommand('insertText', false, text)`; it fires the input event React reads. A `<select>` takes the native `value` setter plus a `change` event, a `datetime-local` input the native setter plus `input` and `change`.
- **A blur does not reach React when the pane does not have focus** (`document.hasFocus()` is false): the rules text, which saves when its box is left, stays unsaved after `element.blur()` or focusing another field. Dispatch `new FocusEvent('focusout', { bubbles: true })` on it, or check that the pane has focus.
- **The clipboard is refused in the pane** ("Document is not focused"): "Copy viewer link" then shows its `prompt` fallback with the link, so a check can read the link from the prompt (override `window.prompt`) but not the "Copied" state. Override `window.confirm` likewise to cancel or accept a confirm.
- **A pane that is not drawn freezes CSS transitions and cannot take a screenshot** (it times out): computed colours then read mid-transition (a border still orange after the field was fixed). Add `*{transition:none !important}` before reading styles, and read the page as text or from the DOM.
- **One account in two tabs shows no "is editing" tag** (the own entry is not shown, and a hidden tab does not announce focus): the tag needs a second account.
- **Admin screens in the screens project** need an admin: a temporary local change of `canAdmin` in `AuthProvider.tsx` that also accepts `window.__FAKE_ADMIN__`, set by the spec, restored before committing and never committed; the rest of the app is served by the same test hooks as the viewer screens, so only fixture ids are opened.
- **Never open a real tournament id on localhost** (the dev browser is an admin and writes); use fixtures there and the test site for a real run.
- **A generated but unstarted fixture**: `upcoming-info` and `upcoming-teams-13` have no rounds (`beforeStart()` clears them), so they show what an admin sees before Generate. For an admin's view between Generate and Confirm & Start, take a pooling fixture (`ffa37-pooling`) with `started: false`, `curRound: 0` and no scores. The `__FAKE_ADMIN__` change makes the server and the page disagree on admin, so the dev server logs a hydration warning; it is harmless there.
